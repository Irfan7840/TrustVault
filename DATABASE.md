# TrustVault — Database Reference & Schema Documentation

> **Version:** 1.0  
> **Engines:** SQLite 3 (Development & Automated Testing) / PostgreSQL 15+ (Production)  
> **ORM:** SQLAlchemy 2.0+ with Flask-SQLAlchemy 3.1+  
> **Migration Engine:** Alembic via Flask-Migrate 4.1+  

---

## 1. Overview & Architectural Intent

TrustVault's database schema is designed around zero-trust authorization, strict relational integrity, and cryptographic non-repudiation.

1. **Foreign Key Enforcement & Cascades**: Foreign keys strictly govern user and document relationships (`CASCADE` for owned assets, `SET NULL` on audit actors).
2. **Deterministic Cryptographic Audit Chaining**: The `audit_logs` table forms a sequential SHA-256 Merkle-like chain where each record stores the SHA-256 hash of its predecessor, guaranteeing tamper-evidence.
3. **UUID-Isolated Physical Storage**: The `documents` table maps human-readable metadata to randomized UUID filenames on disk (`uuid_name`), decoupling file system paths from primary keys.

## 3. Data Dictionary

### 3.1 `users` Table
Stores authenticated identities and roles.

| Column Name | SQL Type | Nullable | Constraints & Defaults | Description |
|---|---|---|---|---|
| `id` | `INTEGER` | No | `PRIMARY KEY AUTOINCREMENT` | Unique internal user identifier. |
| `username` | `VARCHAR(64)` | No | `UNIQUE`, Indexed | Unique username chosen during registration. |
| `email` | `VARCHAR(120)` | No | `UNIQUE`, Indexed | User's verified email address. |
| `password_hash`| `VARCHAR(256)` | No | None | PBKDF2:SHA256 salted hash generated by Werkzeug. |
| `role` | `VARCHAR(20)` | No | Default: `'OWNER'` | Role: `'ADMIN'`, `'OWNER'`, or `'VIEWER'`. |
| `is_active` | `BOOLEAN` | No | Default: `TRUE` | Soft-deactivation flag; deactivated users cannot log in. |
| `created_at` | `DATETIME` | No | Default: UTC now | Account creation timestamp. |

**Indexes:**
- `ix_users_username` on `username` (`UNIQUE`)
- `ix_users_email` on `email` (`UNIQUE`)

---

### 3.2 `documents` Table
Stores file metadata and owner attribution.

| Column Name | SQL Type | Nullable | Constraints & Defaults | Description |
|---|---|---|---|---|
| `id` | `INTEGER` | No | `PRIMARY KEY AUTOINCREMENT` | Numeric ID for internal references. |
| `uuid_name` | `VARCHAR(36)` | No | `UNIQUE` | UUIDv4 string pointing to `storage/documents/<uuid>.dat`. |
| `original_filename` | `VARCHAR(255)` | No | None | Sanitized filename supplied at upload time. |
| `file_size` | `INTEGER` | No | None | Exact file size in bytes. |
| `mime_type` | `VARCHAR(128)` | No | None | Validated MIME type (e.g. `application/pdf`). |
| `title` | `VARCHAR(200)` | No | None | Display title for search and listing. |
| `category` | `VARCHAR(50)` | No | Default: `'General'` | Category tag (General, Financial, Legal, Security, etc.). |
| `description` | `TEXT` | Yes | None | Optional user-supplied description. |
| `owner_id` | `INTEGER` | No | `FOREIGN KEY (users.id) ON DELETE CASCADE`, Indexed | User who uploaded and owns this document. |
| `created_at` | `DATETIME` | No | Default: UTC now | Upload timestamp. |
| `updated_at` | `DATETIME` | No | Default: UTC now, auto-update | Last metadata modification timestamp. |

**Indexes:**
- `ix_documents_owner_id` on `owner_id`
- Unique constraint on `uuid_name`

---

### 3.3 `document_permissions` Table
Granular Access Control List (ACL) mapping users to documents with specific rights.

| Column Name | SQL Type | Nullable | Constraints & Defaults | Description |
|---|---|---|---|---|
| `id` | `INTEGER` | No | `PRIMARY KEY AUTOINCREMENT` | Permission grant identifier. |
| `document_id` | `INTEGER` | No | `FOREIGN KEY (documents.id) ON DELETE CASCADE`, Indexed | Target document. |
| `user_id` | `INTEGER` | No | `FOREIGN KEY (users.id) ON DELETE CASCADE`, Indexed | Grantee user receiving access. |
| `permission_level` | `VARCHAR(10)` | No | Default: `'READ'` | Access level: `'READ'` or `'EDIT'`. |
| `granted_by_id` | `INTEGER` | No | `FOREIGN KEY (users.id)` | User who created the permission grant. |
| `granted_at` | `DATETIME` | No | Default: UTC now | Timestamp grant was created. |

**Indexes & Constraints:**
- `uq_doc_user_permission` `UNIQUE(document_id, user_id)`: Prevents duplicate permissions for the same user-document pair.
- `ix_document_permissions_document_id` on `document_id`
- `ix_document_permissions_user_id` on `user_id`

### 3.4 `audit_logs` Table
Immutable, hash-chained log of all security-relevant and administrative actions.

| Column Name | SQL Type | Nullable | Constraints & Defaults | Description |
|---|---|---|---|---|
| `id` | `INTEGER` | No | `PRIMARY KEY AUTOINCREMENT` | Sequential audit record ID. |
| `timestamp` | `DATETIME` | No | Default: UTC now, Indexed | Precise UTC event timestamp (seconds resolution). |
| `user_id` | `INTEGER` | Yes | `FOREIGN KEY (users.id) ON DELETE SET NULL`, Indexed | Actor ID; null for anonymous events (failed logins). |
| `username` | `VARCHAR(64)` | Yes | None | Static snapshot of actor username at log time. |
| `ip_address` | `VARCHAR(45)` | Yes | None | IPv4 or IPv6 client address. |
| `user_agent` | `VARCHAR(255)` | Yes | None | Client browser/tool User-Agent string. |
| `event_type` | `VARCHAR(50)` | No | Indexed | Standard event identifier (e.g. `DOC_DOWNLOAD`). |
| `status` | `VARCHAR(20)` | No | None | Execution outcome: `'SUCCESS'` or `'DENIED'`. |
| `resource_type` | `VARCHAR(50)` | Yes | None | Target entity type: `'DOCUMENT'`, `'USER'`, `'PERMISSION'`. |
| `resource_id` | `VARCHAR(100)` | Yes | None | String identifier of targeted entity. |
| `details` | `TEXT` | Yes | None | JSON or text string containing event metadata. |
| `previous_hash`| `VARCHAR(64)` | No | None | SHA-256 hash of previous record (`'GENESIS'` for id=1). |
| `entry_hash` | `VARCHAR(64)` | No | None | SHA-256 digest of this record combined with previous hash. |

**Indexes:**
- `ix_audit_logs_timestamp` on `timestamp`
- `ix_audit_logs_event_type` on `event_type`
- `ix_audit_logs_user_id` on `user_id`

## 4. Cryptographic Hash Chain Integrity

To prevent silent tampering, record deletion, or retroactive log fabrication, each audit log row is cryptographically bound to its predecessor.

### Hashing Algorithm

$$\text{entry\_hash} = \text{SHA256}(\text{previous\_hash} \parallel \text{timestamp} \parallel \text{user\_id} \parallel \text{event\_type} \parallel \text{status} \parallel \text{resource\_type} \parallel \text{resource\_id} \parallel \text{details})$$

Where:
- `timestamp` is formatted as `%Y-%m-%d %H:%M:%S` to ensure deterministic string serialization across SQLite and PostgreSQL engines.
- `previous_hash` for the initial record is `"GENESIS"`.
- Each subsequent record takes the `entry_hash` of record $N-1$ as its `previous_hash`.

### Verification Routine
The verification service (`trustvault/services/audit.py:verify_audit_trail()`) loads all audit records ordered by `id ASC`:
1. Verifies that `record[i].previous_hash == record[i-1].entry_hash`.
2. Recomputes `record[i].compute_hash(record[i].previous_hash)` and checks equality against `record[i].entry_hash`.
3. If any discrepancy is found, it immediately flags the exact record ID and nature of tampering.

### Database CLI Commands

```bash
# Apply pending migrations to current database
flask db upgrade

# Check current database revision head
flask db current

# View migration history
flask db history

# Create a new migration after schema edits
flask db migrate -m "add description"

# Rollback one migration step
flask db downgrade
```
